## 28. <u> Authentication & Authorization </u> -

#### Identity & Token Standards - Authentication Concepts:

- Authentication (AuthN): Verifies the identity of a user (e.g., checking if the provided username and password match database records). It answers the question: "Who are you?"
- Authorization (AuthZ): Determines the permissions and access rights of an already authenticated user. It answers the question: "What are you allowed to do?"

---

### 269. JWT (JSON Web Tokens):

A JSON Web Token (JWT) is a compact, URL-safe string used to securely transmit structured identity metadata between a client and a server. A JWT is split into three distinct sections separated by dots (.): Header, Payload, and Signature.

[ Header ] . [ Payload ] . [ Signature ]

#### The Structure Breakdown:

1.  Header: Specifies the token type (JWT) and the hashing algorithm used to sign it (e.g., **HMAC SHA256**).
2.  Payload: Contains the custom user claims (e.g., userId, username, expiration timestamps, or security roles). Warning: The payload is simply **base64-encoded**, not encrypted. Anyone can decode it, so it must never contain sensitive credentials like passwords.
3.  Signature: Generated by taking the encoded header, encoded payload, and running them through a secret cryptographic key held exclusively by your backend server. This signature allows the backend to verify that the token's contents have not been altered or tampered with by the client.

#### The React Context:

React apps intercept this token upon successful login and typically append it to the HTTP Authorization header as a Bearer token for subsequent API requests:

headers: { 'Authorization': `Bearer ${accessToken}` }

---

### 270. OAuth 2.0 & OpenID Connect (OIDC):

**OAuth 2.0** is an industry-standard framework used for delegated authorization. It allows a user to grant a third-party application (your React frontend) limited access to their resources on a service provider (e.g., Google or GitHub) without sharing their password.

**OpenID Connect (OIDC)** is an identity verification layer built directly on top of OAuth 2.0. While OAuth 2.0 returns an Access Token designed to let a server access resources, OIDC returns an ID Token specifically packaged to share user profile metadata (like email addresses and profile pictures) with the client application.

#### The PKCE Flow (Proof Key for Code Exchange):

Because client-side single-page applications cannot securely store private client secrets, they must use the Authorization Code Flow with PKCE to authenticate safely with OAuth providers:

```js
[ React App ] --- 1. Redirect with Code Challenge ---> [ Identity Provider ]
[ React App ]  [ Identity Provider ]
[ React App ] <--- 4. Validates & Returns Tokens ---- [ Identity Provider ]
```

1.  The Challenge: Your React application generates a random, cryptographically secure string called a Code Verifier and hashes it to create a Code Challenge.
2.  The Request: The app redirects the user to the OAuth provider, passing along the Code Challenge.
3.  The Callback: The provider authenticates the user and redirects them back to your React app with a temporary Authorization Code in the URL query string.
4.  The Exchange: Your React app grabs that code from the URL and sends an active background request to the provider's token endpoint, attaching the original unhashed Code Verifier. The provider hashes the verifier, checks it against the original challenge, and returns the formal identity tokens securely, eliminating the risk of authorization code interception.

### 271. Lifecycle Workflows - Login & Signup Flows:

To ensure a secure user experience, forms handling authentication inside React should follow strict integration patterns.

```tsx
import React, { useState } from "react";

export function AuthenticationForm({ onAuthSuccess }) {
  const [formData, setFormData] = useState({ email: "", password: "" });
  const [errorMessage, setErrorMessage] = useState<string | null>(null);
  const [isSubmitting, setIsSubmitting] = useState(false);

  const handleInputChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setFormData((prev) => ({ ...prev, [e.target.name]: e.target.value }));
  };

  const handleFormSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setIsSubmitting(true);
    setErrorMessage(null);

    try {
      const res = await fetch("https://example.com", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(formData),
      });

      if (!res.ok) {
        const errorData = await res.json();
        throw new Error(errorData.message || "Authentication failed.");
      }

      const { user, accessToken } = await res.json();

      // Hand the authenticated metadata off to global state (Context/Redux)
      onAuthSuccess(user, accessToken);
    } catch (err: any) {
      setErrorMessage(err.message);
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleFormSubmit}>
      {errorMessage && <div className="alert-error">{errorMessage}</div>}
      <input
        type="email"
        name="email"
        value={formData.email}
        onChange={handleInputChange}
        required
      />
      <input
        type="password"
        name="password"
        value={formData.password}
        onChange={handleInputChange}
        required
      />
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Authenticating..." : "Sign In"}
      </button>
    </form>
  );
}
```

### 272. Token Refresh & Session Management:

To protect your application if a token is intercepted, access tokens are designed to expire quickly (e.g., `after 15 minutes`). To keep the user from having to log in again every 15 minutes, you implement an automated background Token Refresh mechanism.

#### The Interceptor Pattern:

Using an HTTP library like Axios, you can configure an interceptor to act as an automated sentinel layer. If an API request fails because an access token has expired (returning a 401 Unauthorized status), the interceptor catches the error, pauses the request, fetches a fresh access token in the background, and seamlessly retries the original request.

```tsx
import axios from "axios";

const api = axios.create({ baseURL: "https://example.com" });
// Intercept outgoing requests to attach the active in-memory access token
api.interceptors.request.use((config) => {
  const token = getInMemoryAccessToken(); // Pull token from global state
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
// Intercept incoming responses to handle token expiration errors automatically
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // Check if the server returned a 401 error and that we haven't already retried this request
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;

      try {
        // Request a fresh access token from the backend
        // The secure httpOnly refresh cookie is automatically attached by the browser
        const { data } = await axios.post("https://example.com/auth/refresh");

        updateInMemoryAccessToken(data.accessToken); // Update global state

        // Update the failed request's header with the fresh token and retry it
        originalRequest.headers.Authorization = `Bearer ${data.accessToken}`;
        return api(originalRequest);
      } catch (refreshError) {
        handleGlobalLogout(); // If the refresh token is also expired, force a logout
        return Promise.reject(refreshError);
      }
    }
    return Promise.reject(error);
  },
);
```

#### Logout Handling:

Logging out a user requires clearing authentication data from both the client application and the server to prevent session hijacking.

#### The Steps for a Complete Logout:

1.  Invalidate Server Session: Send a request to your backend's logout endpoint. The server will delete the active session records from its database or add the user's tokens to a blacklist.
2.  Clear Client State: Reset your React global application state, wiping out all in-memory user objects and access token strings.
3.  Purge Storage & Cookies: Clear out any cache stores or transient local storage markers, and clear the authentication cookies via the server's response headers.
4.  Redirect: Use your router to programmatically redirect the user back to the public login screen.

### 273. Access Control Architecture - Protected Routes & Role-Based Access (RBAC):

To restrict access to parts of your application based on authentication status or user permissions, combine Protected Routes with Role-Based Access Control (RBAC).

```tsx
import { Navigate, Outlet, useLocation } from "react-router-dom";

type ProtectedRouteProps = {
  isAuthenticated: boolean;
  userRole?: string;
  allowedRoles?: string[];
};
export function AccessControlBoundary({
  isAuthenticated,
  userRole,
  allowedRoles,
}: ProtectedRouteProps) {
  const location = useLocation();

  // 1. If the user is completely unauthenticated, redirect them to the login page
  if (!isAuthenticated) {
    // Save their current location in history state so we can redirect them back after they log in
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  // 2. If the route requires specific roles and the user doesn't have them, block access
  if (allowedRoles && (!userRole || !allowedRoles.includes(userRole))) {
    return <Navigate to="/unauthorized" replace />;
  }

  // 3. If all checks pass, render the protected nested components
  return <Outlet />;
}

// Usage Configuration in the Router Tree

<Routes>
  {/* Public Routes */}
  <Route path="/login" element={<LoginScreen />} />
  <Route path="/unauthorized" element={<UnauthorizedScreen />} />

  {/* General Protected Routes (Requires Authentication Only) */}
  <Route element={<AccessControlBoundary isAuthenticated={isLoggedIn} />}>
    <Route path="/dashboard" element={<GeneralDashboard />} />
    <Route path="/profile" element={<UserProfileSettings />} />
  </Route>

  {/* Premium/Admin Only Protected Routes (Requires Explicit Role Permissions) */}
  <Route
    element={
      <AccessControlBoundary
        isAuthenticated={isLoggedIn}
        userRole={currentUser?.role}
        allowedRoles={["admin", "premium_manager"]}
      />
    }
  >
    <Route path="/admin/analytics" element={<EnterpriseAnalytics />} />
    <Route path="/admin/billing" element={<GlobalBillingPortal />} />
  </Route>
</Routes>;
```
